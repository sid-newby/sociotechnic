# Final independent review: prompt candidates

## Decision

**PASS for the 20 changed prompt candidates, with two explicit scope caveats.** I found no must-fix correctness, scope, output-path, tool-permission, blocked/retry, trust-boundary or verification contradiction in the selected role bodies when composed with current generated briefs and role tools. The candidates instruct agents to use generated brief paths/schemas and retain existing status and record vocabularies; they do not introduce a checkpoint status or claim context occupancy telemetry.

This is a prompt package review, not a publication authorization or a live model quality assessment. The offline validator passed: 38 source releases / 22 latest agents, 20 changed / 2 retained, 42.6% source-body byte reduction, 20 prepared API payloads. Source settings/skills and format compatibility were checked by `prepare-agent-prompt-candidates.mjs`; this cannot show that a model will follow instructions, validate records deterministically, or implement a fresh continuation checkpoint.

## Caveats to keep in the publication note

1. **Conformance and required record sections remain nondeterministic.** Candidates now tell agents to provide complete records, but the installed parser does not require the build/research/review/decision headings or complete conformance stage coverage. The probe script `scripts/audit-handoff-contracts.mjs:8-15,32-49` is synthetic parser/gate evidence, not an end-to-end model test. Keep the package claim scoped to prompt improvements; strict body checks need separate versioned engine work so old pinned runs are not retroactively invalidated.
2. **Two roles are retained, not refreshed.** `sociotechnic-designer` and `sociotechnic-comment-sicko` are byte-identical to source. In particular, retained Sicko still contains its legacy 200k/150k context-byte/token heuristic. It is a nested Sonnet worker; the candidate metadata explicitly defers it pending independent deployment provenance. If the user expects every active prompt to stop using that heuristic before the handoff refresh is considered complete, this package does not meet that scope. Do not silently alter or claim it was updated.
3. **No fresh continuation/checkpoint protocol is introduced.** The normal dispatch already launches a fresh agent on retry (`src/engine.ts:188-213`), and every builder round has one builder dispatch (`src/engine.ts:431-441`), but there is no optional continuation artifact or separate state transition here. These candidates wisely preserve READY/BLOCKED; they cannot be represented as adding checkpoint behavior. Context use fields remain completed-dispatch/turn usage, not active occupancy (`ui/runner.ts:110-122`; `ui/codex-runner.ts:24-29,139-145`).
